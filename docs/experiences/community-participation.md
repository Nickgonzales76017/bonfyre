# Community participation

## Release status

Implemented and tested in the native checkout, then included in the public
participant-return release on October 21, 2026. Both web and CMS executables were
promoted together. Public discovery and exact guest continuations were checked
over HTTPS. Customer-account writes were not used for release verification.

## Discover, join and return

Open Communities to search local communities. Their conversations are public;
reading does not require an account. An observed external group remains a
source reference and does not become a locally controlled community.

Choose Request to join when you want to contribute. Sign-in retains the exact
community and requested section. Sending the request is a separate action.
The steward accepts or declines it within that community. A pending request
is not an active membership.

The private Profile > Communities section shows your requests and memberships.
Open conversations there to return to the same community. This section is not
shown on your public profile sites. Contributing to a community does not copy
content onto your WORK, LIFE, LIVE or SHOP profile.

## Conversations

Active members can start a titled conversation and reply to a contribution.
Review the exact public text before publishing. Each contribution retains its
own author and parent. A selected reply has links to its parent and the start
of the conversation. Lists are bounded pages, not an unbounded feed.

Authors can edit their own visible text while their membership is active.
An old form cannot overwrite a newer edit. Authors can remove their own words;
other people's replies keep their identity. Removed text is not rendered, and
a removed ancestor prevents new replies through that branch.

The steward may hide a contribution, but cannot rewrite another author's words.
Unrelated organization administrator rights do not add community controls.

## Start and manage a community

Start a community from the directory or your private profile. Name its purpose
and guidelines, review the public introduction, and confirm creation. Native CMS
commits the community and its founding stewardship together, or rolls both back.

People and requests is available only to that community's steward. Accepting,
declining and ending participation affect that community alone. Revoked or
declined participation cannot be converted into a fresh request by leaving.
Members can withdraw a pending request or leave their active membership.

## Interrupted work and boundaries

Reusing the same successful creation or publishing request does not duplicate
its result. Conflicting reuse is refused. An unreadable response is not success:
open the current community before explicitly retrying the retained exact request.
The server never repeats the write automatically.

This implements public, locally authored community conversations. It does not
supply private groups, invitations, multiple delegated stewards, notifications,
blocking, reports/appeals, media attachments, external-network posting, commerce,
event registration, funded programme delivery, or completion of all 388 flows.

## Existing native owners and verification

Auth resolves the current actor. Existing root-namespaced community_body,
community_membership and community_post records remain owned by BonfyreCMS.
The new community-work operation commits through native CRUD, deferred hooks,
current-state checks and native fact-delta delivery. WebAddress renders bounded
pages, exact thread relationships and the private profile continuation. It does
not introduce another business-record store or grant infrastructure privileges.

The normal make test target now includes community-journey-witness. Its final
run passed 29 community/profile tests with 325 assertions. Separate navigation,
QR, audio, RSS and house/WORK presentation suites passed 48 tests; the four-site
session test passed after supplying its existing catalogue fixture. The two-user
and guest-login browser checks use isolated native owners, not customer accounts.

Canonical Atlas registration remains pending: architecture/surface is outside
the current low-risk write boundary. There is no claim that a passing existing
Atlas validation would register this new owner bridge. The participant-return
release did not change operator STOP or create a production community, test
member or sample post. The previous service configuration is retained for rollback.
