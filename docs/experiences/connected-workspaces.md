# Connected workspaces

The first connected configuration implementation keeps the existing catalogue,
product inspection and room editors. It changes their storage and hosting owner,
not their specialized interaction model. The native release is deployed. Both
connected configuration pages were read back on WORK, LIFE, LIVE and SHOP.
The complete editing and adoption journeys passed against isolated native
accounts and stores using the released package. No live test account was created.

## Working journey

Review the configuration, select your personal workspace, an organization in
which you hold an administrator grant, or a household you can administer.
Installation atomically retains dependency pins and creates destination-specific
application bindings. Activation is a separate operation. Open the catalogue
from its active configuration, inspect a product, choose a quantity and place it
in a room. The room keeps its product identifiers, fixture identifiers, prices,
source model bytes and plan identity. Another authorized organization member can
open that same plan through a separately installed room editor.

Organization writers may edit; readers may inspect. Installing a configuration
does not create either grant. The household follow-up release adds explicit
membership: readers inspect, writers edit, and administrators configure apps.
Only the recorded household steward manages memberships. From the selected
household's configuration page, open **Household access**, enter an existing
account's email, review the member and choose their access level.

Removing access preserves saved household work. Revoked and expired access is
checked again by the native owner; changing the steward away and back does not
revive old grants. The form does not create accounts, send invitations or
transfer stewardship. Renewal of an existing expiry has no dedicated form yet.

## Draft preservation

Native editors save through CMS using bounded binary records and exact revision
checks. A stale save cannot overwrite another member. Multi-record edits either
commit together or fail. Source model files retain their original bytes and are
verified before their draft references become usable. Deactivation and removal
do not delete destination drafts. A failed native save never falls back to a
different browser-local draft.

Existing public-demo drafts remain on their original browser origin. The
explicit browser transfer requires source selection followed by
destination review. Conflicting drafts require a deliberate replacement choice.
The two-origin browser witness passed thirteen checks, including model-file
preservation, unchanged source revisions and refusal of stale replacement.
Source submission receipts are cleared in the adopted destination copy; the
original plan, fixture identities and original browser receipt remain intact.

Catalogue-to-room continuity is not supplier ordering or merchant publication.

## Open the connected release

Use Aurekai setup and choose **Catalogue — shared workspace** or **Room Planning
— shared workspace**. Their native coordinates are
`experience.multi-merchant-catalogue.workspace` and
`experience.retail-procurement.workspace`. These application releases depend on
the existing portfolio products without rewriting their workflow-only releases.
Existing accounts are not automatically enrolled or upgraded.

Both editors share the same destination's Spaces record family. That is why a
catalogue selection and its saved plan can move into the room editor without a
second plan identity. A different organization, household or personal workspace
has a different record family. Changing destinations is never an implicit copy.

## Shared audio arrangements

Choose **Audio Studio — shared workspace** in Aurekai setup. Its coordinate is
`experience.native-creator-studio.workspace`. Install it in the intended personal,
organization or household destination, activate it, then open its audio editor.
The existing sources, waveform timeline, clip edits, playback and WAV export stay
in that editor. Recordings and edits save through the native owner; another
authorized member can reopen the same session. A stale save cannot overwrite
their newer edit.

**Bring browser drafts** opens the Work Samples audio source. Select the saved
session there, then review adoption in the destination. The original recording
bytes, clip coordinates and source browser revision remain intact. Recording
permission resets to unreviewed for the recipient. Private training records are
not offered by the audio transfer. Exporting a WAV does not publish a channel or
grant rights over the recording.

## Links and the source library

The public Links, Sources and ForeignTwin workbench entrances now use the same
native source desk. The catalogue searches already-known source contracts;
searching it is not whole-web search. The October source release was read back
on public HTTPS with 2,600 contracts, exact publisher filtering, desktop and
phone layouts, and no uncaught JavaScript errors. Distinct source contracts
remain separately addressable even when a legacy twin identifier was truncated.

Choose **Source library** in setup, or open it under **Your work** after
activation. The pack is `experience.source-library.workspace` and stores private
`source-material:` records in the selected native destination. Review up to
24 files or addresses together, assign collections and tags, and retain exact
original bytes. The library reads metadata first; selecting an original causes
its verified file chunks to load. Editing a title or note, archiving and
restoring do not replace the original or downstream research.

Select active UTF-8 text, Markdown, CSV, subtitle or RIS sources and choose
**Prepare research**. The receiving research editor must be installed in the
same destination. Review a new or existing research record, then save. Original
text, source identity and revision are carried into the receiving editor;
existing findings and source selections remain intact. PDFs and other binary
files can be retained and downloaded, but this release does not claim text
extraction from those formats.

## Operational boundaries

The native record wire format is bounded MessagePack, not a JSON snapshot store.
Save batches use expected revisions and retained idempotency receipts. Source
files use verified 256 KiB chunks, a 24 MiB per-file limit and a 128 MiB retained
file budget per destination family. Metadata batches are bounded to 512 KiB and
each value to 256 KiB. An exceeded limit refuses the operation rather than
silently dropping files. Unreferenced uploaded bodies can remain retained after
a failed or cancelled adoption; automatic reclamation is not implemented here.

Training's member-private synchronization, Brief Studio and ITAD installation
adapters, supplier orders, merchant publication and creator-to-channel delivery
remain separate integration work. The audio adapter preserves the existing
editor's bounded recording and timeline limits; it does not add other codecs or
a long-form production engine.
