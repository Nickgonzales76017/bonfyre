## One piece of work, several ways in

A customer uses the finished site or app. An agency looks after several customers and keeps them apart. A developer calls the same thing from a command or a library. An assistant reaches it as a tool over MCP, with only the access it was given. All four are looking at the same records.

| Way in | What it is for |
|---|---|
| Website | Pages, search, enquiries, bookings and publishing |
| Agency workspace | Each customer's settings, people and deployments |
| Command line and library | Building, inspecting and scripting |
| MCP | Letting an assistant read or act within set limits |
| These guides | Steps you can run, with the result you should see |

[One application, several interfaces](/interfaces-and-mcp) shows the same page read each way.

## Keep each customer separate

A customer's site carries their own address, design, content and tools. A key issued for one customer does not open another customer's data. The [white-label guide](/white-label-delivery) sets up three sites and then shows a request across customers being refused.
