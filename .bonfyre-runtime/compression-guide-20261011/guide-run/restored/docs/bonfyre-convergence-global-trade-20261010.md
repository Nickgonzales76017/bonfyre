## International markets: one operation, many document/partner profiles
Country-by-country clones are a trap. The same protocol/commerce/finance owners can serve a Texas buyer, Mexican garment atelier, Indian exporter, Vietnamese manufacturer, Brazilian distributor and Chinese component maker. Local grammar adds document issuers, language, HS rules, region, Incoterm, currency, FX source, inspection, lead time, origin/proof and agency/contact carrier.

A buyer-led cross-border order has a single identity and distinct real observations:
Buyer requirements + acceptance test -> suppliers verified independently -> request for quote -> part/lot revision and true manufacturer/trader -> MOQ/samples/quality/certificates -> supplier quote and currency/expiry -> INCOTERM plus named place -> freight, insurance, HS and origin/duties/broker -> delivery/financing timeline -> accepted customer bid -> real invoice/order -> shipment/delivery/proof -> settlement/net contribution -> repeat. Carry missing pieces as open, never fill with simulated bids.

Existing projected ERPNext Quotation already has incoterm, named_place, currency, conversion_rate, supplier_quotation and totals. Use these first, not a new TradeQuote table.
