## [0.8.0-alpha.1] — 2026-05-02

Aurekai v0.8.0-alpha.1 introduces the public platform layer for the Bonfyre native runtime.

This release adds the `akai` CLI, Aurekai deployment metadata, first-class `.akmodel`/`.aksae`/`.akfpqx` aliases, Bonfyre compatibility manifests, Helm and VS Code scaffolds, SHA256SUMS, SBOM output, and an end-to-end release-check that validates the underlying runtime with `doctor --deep`.

### Added

- `akai` CLI front door delegating to the Bonfyre HyperRuntime
- `AUREKAI_*` environment variable aliases alongside all `BONFYRE_*` vars
- First-class `.akmodel`, `.aksae`, `.akfpqx` artifact formats
- `aurekai.manifest.json` — public distribution metadata schema (`aurekai.deploy.v1`)
- `bonfyre.manifest.json` — included in every release as the legacy runtime validation bridge
- `SHA256SUMS` and `SBOM.spdx.json` generated by `make sha256sums sbom`
- Deployment manifest sections: `model_memory` (dual `akmodel`/`bfmodel`), `sae_dicts`, `fpqx_alignments`
- Default SAE dict discovery chain: `AUREKAI_SAE_DICT` → `BONFYRE_SAE_DICT` → `default.aksae` → `default.bfsae`
- `akai install` creates an `akai` binary alias alongside `bonfyre-hyper`
- macOS launchd service `ai.aurekai.runtime` with `AUREKAI_*` + `BONFYRE_*` env vars
- Linux systemd service `aurekai-runtime.service`
- Helm chart skeleton: `aurekai-runtime` (deployment, service, values, helpers)
- VS Code extension skeleton: `aurekai-workbench` with `.akmodel`/`.aksae`/`.akfpqx` language contributions
- GitHub Actions release workflow triggering on tag `v*` with prerelease support
- Ecosystem registry map: `registry/public-surfaces.json` (GitHub, npm, PyPI, GHCR, HuggingFace, Homebrew, Helm, VS Code)
- `scripts/split-aurekai-repo.sh` — one-command extraction to standalone `github.com/aurekai/aurekai`

### Compatibility

Legacy `bonfyre` / `bonfyre-hyper` commands continue to work unchanged.  
`.bfmodel`, `.bfsae`, `.bffpqx` remain fully supported alongside their `.ak*` aliases.
