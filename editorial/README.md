# Aurekai Journal — public articles and editorial source

The Aurekai Journal currently holds **64 edited articles**: sixteen essays based on earlier Aurekai/Bonfÿre work, thirty additional pieces examining external research, mathematical claims, tools, markets, standards, and original posts on X, plus eight essays on living web presences and accessible software ecosystems, five essays on independent judgment and expression, and five essays on internet operators, preservation and ownership.

The editorial Markdown in `editorial/posts/*.md` is authoritative. Each article has a stable slug, canonical URL, category, icon, publication date, source lineage, and `status: edited-public`. Posts responding to outside material include a `source_url` for the primary source. These are independently written articles, **not raw chat exports or endorsements by the cited organizations**.

## Static publication

From the public repository root:

```sh
sh scripts/render-editorial.sh
sh scripts/render-editorial.sh --check
```

The shell wrapper uses the Python 3 standard library available on the Pages runner. It produces `site/blog/index.html`, one HTML page per article, `feed.xml`, `sitemap.xml`, and `post-index.tsv`. The published HTML is built from source inside GitHub Actions immediately before the Pages artifact is uploaded. The independent **Aurekai Journal Validation** workflow performs the same deterministic check on every editorial change.

No new installed JavaScript program is introduced, and the native code-budget ratchet remains unchanged. The original static journal's client-side search runs as a small inline enhancement; all article links and the feed work without it.

## Native publishing integration later

The TSV manifest maps each post to a stable `post:<slug>` identity and the original Markdown path, SHA-256, canonical URL, and cited primary source URL. BonfÿreCMS / Matrix / Source Library can consume these records later while retaining the existing public article URLs.

A public article must be reviewed before setting `status: edited-public`. Do not publish raw project conversation logs, private customer details, credentials, account tokens or unpublished integration contracts. Attributed quotations should be short and linked to their original context; mathematical examples must identify hypothetical inputs instead of presenting them as measured results.

## Article-level editorial direction

The 66 articles are individually assigned a nonrandom publication format and colorway in `scripts/render-editorial.sh`. Fourteen semantic formats distinguish reporting, dossiers, cultural features, business analysis, systems research, archives, and designed opinion columns. There are **no procedural botanical illustrations**, arbitrary species names, or autogenerated artwork in this pipeline. Some stories use **real photographs licensed as public domain/CC0 or verified first-party product screenshots**, with clear attribution linked to the underlying source. Others use typographic covers with real section headings from the authored essay, rather than a misleading decorative picture. The Journal cover uses a credited photograph by Austin Schmid (CC0 via Wikimedia Commons). The reader can inspect the article's editable Markdown and sources.

Keep the article-level manifest maintained when adding an essay; it is an intentional editorial decision. The existing journal check fails if any post has no art direction, if a procedural `cover.svg` remains, if credited media is not identified, or if the edition styles are missing. The site generates static HTML/CSS with no paid model or image-generation dependency.

## Spoken editions and audio delivery

Every article embeds a prominently placed audio player in its editorial opening, not an unlabeled utility link below the fold. For an article without a recorded file, playback uses the visitor's browser speech voice; the 72-bar timeline represents real passage positions calculated from the authored words, **not** an audio waveform, and seeking restarts at a spoken passage boundary. The player provides play/pause, back/next passage, speed, reading synchronization, resume within a page, and a compact dock while reading. If a rights-cleared narrated audio file is available, the article can add `audio_file: edition.mp3` to its front matter and place that file in `site/blog/<slug>/edition.mp3`; the renderer refuses a missing file, and the client decodes the published recording to draw amplitude peaks and seek by actual time. BonfÿreNarrate can produce the audio but the media must go through an explicit publication review before that front matter is added. Do not label browser speech as a publisher-recorded podcast or claim decorative waveforms are signal measurements.
