01 / TECHNICAL GUIDE · SOURCE BEFORE CLAIMS

Native capabilities.
Verified outcomes.

Bonfÿre is the typed execution engine behind Aurekai. Its job is to preserve institutional context and make software composable: who or what a record belongs to, what a capability actually does, what a task requires, who can authorize an effect and how a result is verified.

RELEASE DISCIPLINE

Code compiled is not work delivered.

A named command, local test, configured provider, remote deployment and paid customer outcome are separate claims. Each needs its own evidence.

02 / SEMANTIC OWNERS

One meaning.
Many realizations.

The Matrix and named organs preserve semantics independently of whichever C command, model, agent, browser UI, SQL database or remote provider happens to realize a job. Upstream code and partner services do not inherit Bonfÿre authority by being integrated.

03 / NATIVE ENGINE

Small parts. Strong contracts.

The engine includes native command families for data, media, models, publishing, identity, work, economic records and external integration. Its size and maturity cannot be summarized truthfully by an old fixed binary count.

04 / AGENTIC EXECUTION

Agents can act.
Not without authority.

Claude Code, Codex, local inference, MCP and other carriers may perform bounded work. They do not own institutional meaning, source truth, finance or permissions. A proposed action is not an approved effect.

05 / MODELS AND OPTIMIZATION

06 / VERIFICATION

Measure the thing
you intend to claim.

Old binary-size totals, selected ASR quality proxies, compression ratios and cloud-provider comparisons are not current platform guarantees. The code revision, corpus, hardware, baseline and independent result must all be specified.

Evidence categoryNecessary proofWhat it does not prove
DeclaredA named contract and architectural ownerThat a callable implementation exists
ImplementedSource, version, direct tests and supported dependenciesThat a remote service is running
MeasuredTest protocol, corpus, baseline, hardware, results and witnessGeneral performance across unrelated tasks
Publicly deployedExact release and destination readbackSuccessful customer completion or settlement
Commercially completedAcceptance, invoice/payment and actual deliverable recordsUniversal deployment or endorsement

Research archive: historical benchmark tables and extensive exploratory FPQ documentation remain available in the previous technical page at its exact Git revision. These may be useful for reproducing experiments, but should not be lifted into contemporary advertising without checking their proof files and the current implementation.
