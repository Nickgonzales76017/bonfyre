Bonfÿre / technical guide

How Bonfÿre
works.

Bonfÿre is the software we use to build and operate Aurekai. It handles the things our different products need in common: people and organizations, their records, business applications, external information, models, agents, transactions and public websites. The same identity or record can appear in several places while each application keeps control of its own work.

The architecture

One identity can have a lot of useful places.

Think about a publisher, a business or an item for sale. It may have a public page, a workspace record, an API address, material in a feed and relationships to other people and organizations. Bonfÿre's Matrix keeps the subject and its relationships together instead of making each appearance a separate source of truth.

An address is more than a URL. The same subject might appear under an Aurekai subdomain, a customer's own domain, an internal account application or an external API. Which parts someone can see depends on the account, the audience and the state of the record. Matrix and Bonfÿre's address owners handle those relationships. The web renderer then builds the view appropriate to that destination.

A cross-application example

What happens to a job posting.

One of our ongoing integration examples starts with a job posted by a company. Several Aurekai applications may want to work with that information, but they don't all have the same job.

The source system retains the posting and the company it belongs to. The public discovery page can show the opportunity. An account's CRM can use it as a relationship or sales opportunity, if that installed application accepts this kind of item. A media tool might use the same text to prepare a narrated update. Each application receives the part it needs and keeps its own work; it doesn't take over the original listing.

That sounds simple when it's one record. It becomes harder across thousands of publishers, companies, catalogues, identities, accounts and external services. Bonfÿre handles the common address, application and capability relationships so each new continuation doesn't need its own custom integration from scratch.

06 / MODELS AND COMPUTE

Models, compute and media.

Model Commons deals with the practical details of running models: loading weights, choosing a machine or backend, using a tokenizer, managing context, compressing and quantizing models, and evaluating the result. Other Bonfÿre components handle speech, transcription, audio, video and publishing. These services are available to the applications that need them.
